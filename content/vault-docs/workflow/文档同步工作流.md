### 工作流
```
# 1. 在 tech-vault 写笔记，在tech-vault仓库提交笔记
cd /Users/qinxike/works/knowledge-vault/tech-vault
git add .
git commit -m "xxx笔记更新"
git push


# 2. 切回quartz站点仓库，同步到content
```

### 同步脚本
在site仓库根目录下，新建一个同步脚本。脚本文件名: sync-notes.sh

#### 坑1: 
不要使用mac默认的rsync，它同步中文文件名编码不一样，会导致提交到git无法识别。
> Mac APFS 存储中文文件名默认是 **NFD（分解式 Unicode）**，Linux（GitHub Action 的 Ubuntu）ext4 文件系统原样接收字节，不会自动归一化；肉眼看文件名一模一样，底层字节不同，git、Quartz 会判定成两个不同文件，后果：
    1. Quartz 内部链接 `[[中文笔记]]` 在 CI 里 404 找不到文件
    2. rsync 每次同步，都误以为文件新增 / 删除，反复全量同步
    3. git 仓库里出现同名、不同编码的两份幽灵文件

- 处理办法: 
    - git全局配置: `git config --global core.precomposeunicode true`
        > 这个参数打开之后，Mac 上 git 入库的时候，**自动把 NFD 转为 NFC（合成标准 UTF8）存入 git 索引**，推送到 github 之后，Linux 检出拿到的就是 NFC 标准文件名。
    - 使用brew的rsync: `brew install rsync`
      > 一定要用 brew 安装的 rsync，不要 mac 自带老 rsync（自带版本不支持 --iconv）

#### 脚本内容:
```
#!/bin/zsh

# 过滤所有.开头的文件, .开头的文件夹
SRC="/Users/qinxike/works/knowledge-vault/tech-vault"
DEST="./content"
rsync -av --delete \
  --iconv=UTF8-MAC,UTF-8 \
  --exclude ".git/" \
  --exclude ".obsidian/" \
  --exclude ".trash/" \
  --exclude ".DS_Store" \
  --exclude ".*/" \
  --exclude ".[^/]*" \
  $SRC/ $DEST/
```
